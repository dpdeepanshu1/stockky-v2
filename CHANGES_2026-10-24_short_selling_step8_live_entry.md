# Short selling step 8 + 9: the live short entry and the 1-share cap (Position Stocks only) - E99

`SHORT_MODE=live` is now accepted and a live short can be opened. It ships **off**, the compose default is still `shadow`, and a live short is at most `SHORT_LIVE_QTY_CAP` shares (ships 1). `orders/entry.py` (the long entry) is not edited.

## What changed
- `orders/short_live.py` (new): `attempt_short_live(db, cand, quality, board_row, now)`. Order of work: live guards (armed, daily-loss kill switch, order budget, opening pause, entry cap, approve-first round, max positions, max live shorts, `USE_SUPER_ORDER` on) -> symbol lock -> `short_entry.plan_short` (the same mirrored gates, levels and sizing the shadow uses) -> size = min(plan, `SHORT_LIVE_QTY_CAP`) -> `ledger.reserve_capital(side="SHORT")` (unused reservation handed back after the cap) -> Dhan security id -> shared order budget -> `place_super_order(SELL, MARKET, INTRADAY)` with the stop leg and target leg -> position row with `side="SHORT"`, order budget counted, Telegram message. Every refusal releases the capital and the symbol lock it took. Never raises.
- A timed-out SELL is looked up at Dhan (`find_recent_buy_order(transaction_type="SELL")`) before the entry is called failed, so a placed short is never left untracked. If the order was sent but the position row cannot be saved, a critical alert names the order id.
- `orders/short_entry.py`: the gate walk is now `plan_short()`, shared by the shadow row and the live entry so they cannot drift. Shadow behaviour is unchanged (same gate order; the two shadow-only checks run at the same point). `cfg_mode()` added; `mode()` still reads `live` as off, so the shadow path can never place an order. `run_short_cycle` now also runs in live mode and hands candidates to `short_live`.
- `config.py`: `SHORT_MODE` accepts `off|shadow|live`; new `SHORT_LIVE_QTY_CAP` (1 .. 1000, ships 1).
- `control/catalog.py`: `SHORT_MODE` has the `live` choice (shadow -> live and off -> live classify as LOOSENS, so the switch needs the confirm; `recommended` stays `shadow`); new `SHORT_LIVE_QTY_CAP` flag (live, up = loosens).
- `calibration-runner-service/autocalib.py`: `SHORT_LIVE_QTY_CAP` is on the PROTECTED list.
- `stockky_full_test.sh` PART 0 runs the new behaviour script.

## Deliberately NOT done (and why)
- **No plain MARKET SELL fallback.** The plan said to fall back to a plain SELL plus service-managed stops when Dhan refuses the SELL Super Order. `stop_watchdog` only watches positions that have a Super Order id, so a plain-order short would have had no stop at all. When Dhan refuses the SELL Super Order, no short is opened. Add the fallback only after T6 shows how Dhan treats SELL Super Orders, together with a watchdog that covers plain orders.
- `overnight_stop.py` and `convert_intraday_to_cnc` already skip / refuse shorts (steps 3 and 4); not touched again.
- Item 10 (exit tests against the real exit code on the VM), item 11 (frontend for live shorts: badge, `live` choice in the page's switch, the card text still says "shadow only") and item 12 are still open.
