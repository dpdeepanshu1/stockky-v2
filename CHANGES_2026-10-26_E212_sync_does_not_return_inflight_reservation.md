# E212 - position-stocks ledger: a manual /ledger/sync no longer hands an in-flight reservation back to the pool

**Where:** services/position-stocks-service/capital/ledger.py (`sync_from_broker` hard reset, `reserve_capital`, `reserve_additional`). Noted-not-changed item from E186.
**Bug:** `reserve_capital` takes the amount out of `available_capital`, but the position row is written a moment later. A `POST /ledger/sync` landing in that gap saw "no open positions" and hard-reset `available_capital` to the full pool, returning the reservation; the entry then went ahead on capital the pool no longer showed as committed. The trading cycle itself is sequential, so only the manual route could hit it.
**Fix:** a reservation (`reserve_capital` or `reserve_additional`) records a monotonic timestamp. For `_RESERVE_GRACE_S` (120 s, constant) after it, the "no open positions" hard reset does not raise `available_capital`; it is only clamped down to the new total (so a lower Dhan balance still shrinks it). After the grace, or once the position row exists (open_count > 0 takes the other branch), behaviour is as before. Process memory only; no column, migration or environment variable.
**Behaviour to expect:** for up to 2 minutes after an entry that never produced a position row and was not released, available capital is not refreshed upward by sync. Failed entries that release capital are unaffected.
**Test rig:** tests/conftest.py autouse fixture clears the marker (`reset_reservation_marker`) around every test.
**Tests:** tests/test_e212_sync_does_not_return_inflight_reservation.py (5). Existing ledger tests only reserve after a sync, so none depends on the old behaviour. NOT RUN (no pytest/SQLAlchemy here); py_compile only. `docs/ENV_REFERENCE.md --check` passes.
