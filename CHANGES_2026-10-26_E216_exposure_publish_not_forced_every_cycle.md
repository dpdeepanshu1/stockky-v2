# E216 - position-stocks: sync_from_broker no longer force-publishes the exposure row every cycle (E186 leftover)

**Why:** `capital/ledger.py::sync_from_broker` called `publish_exposure(db, force=True)` at the top of every cycle, i.e. two Oracle writes (exposure + daily P&L) about every 13 s, although the cycle already publishes through the throttle (main.py) and the non-forced path writes whenever the figure changes and at least every 30 s (`_EXPOSURE_PUBLISH_MIN_INTERVAL_S`), still BEFORE the funds read can fail. The peer's stale mark is 15 minutes, so a 30 s heartbeat is ample.
**Change:** `publish_exposure(db)` (no `force`). `force=True` stays available for callers that want it. test_group193_publish_exposure.py needed no change (its fixture resets the throttle state, so the funds-failure test still sees one publish).
**Decided not to build (with reasons):**
- E181/E183 persisted retry state: needs a new column + migration; the loss is only a restart inside the 12-minute EOD retry window, and the positions are then retried as ordinary OPEN ones. Not worth a schema change.
- E180/E184: depend on Dhan's real responses (cancelled part-filled super order, keeping capital reserved on an unknown short SELL); cannot be settled without a live capture.
- E186 manual `POST /ledger/sync` landing between `reserve_capital` and the position row: admin-only route, window of milliseconds; left.
**Review of the 26 Oct loss (no code change):** the same-day symbol block and the 3-stop-out day pause already exist (group 479, orders/stopout_guard.py). SIGNATURE (12:54) and SUNTV (12:56) were opened while only 2 losing stop-outs had closed (SSWL, FEDFINA), so the pause had not triggered. SSWL's two stop-outs were on different days (23 Oct and 26 Oct), so a same-day block would not have helped. Lowering STOPOUT_DAY_PAUSE_N to 2 would have saved about 44 on 26 Oct but cost about 60 of winners on 23 Oct, so it was left at 3.
**Tests:** `python3 -m py_compile` on capital/ledger.py. pytest NOT run (not installed here): `pytest tests/test_group193_publish_exposure.py tests/test_ledger_stale_sync_e186.py tests/test_e215*` in position-stocks-service.
