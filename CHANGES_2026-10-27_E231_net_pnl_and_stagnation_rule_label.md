# E231 (2026-10-27) - both services reported on one P&L basis, and the stagnation exit says which rule fired

From the 27 Oct deep dive of the trades CSVs and the latest results. Reporting only: no trading rule, order or setting changes.

1. **Position Stocks P&L is now NET of charges in the reports.** `realized_pnl` of a position-stocks trade is before charges, while real-trade's `net_pnl` is after them, and `daily_trade_report.py`, `service_onoff_advice.py` (it reuses the daily report's rows) and the frontend Trades CSV / totals (`calibrationTrades.ts`) summed the two as if alike. On the 19-27 Oct window that showed -311 combined; on one basis it is about -341 (real-trade -242, position-stocks -99, not -69). Win / loss is now counted on the net figure, so a "win" smaller than its charges (AJMERA +2.52 against 2.74 charges) is a loss. A row whose charges are unknown (null) is left as it was.
2. **Which stagnation rule fired is recorded.** Both the 30-minute flat-band rule and the 20-minute no-follow-through rule close as `STAGNATION_EXIT`. `orders/eod_squareoff.py::run_stagnation_exit` now stamps `flow_json["exit_rule"]` = `flat_band` | `no_followthrough` before it closes (record only, never raises, keeps the other flow_json keys, leaves an unreadable value alone). No new column, so no migration. `GET /trades/history` returns it as `exit_rule` (null for other exits and for rows closed before E231). The daily report and the Trades CSV show the reason as `stagnation_exit:flat_band` / `stagnation_exit:no_followthrough`; older rows keep the plain `stagnation_exit`.

Not changed (your call): the 0.8% / 1.6% levels, the 20-minute no-follow-through rule and its 0.5% minimum gain. The data so far (12 position-stocks trades) is too thin to judge them; with the rule now labelled, a few more days will show which one helps.
