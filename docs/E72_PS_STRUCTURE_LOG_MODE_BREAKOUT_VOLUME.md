# E72 - Position Stocks structure gate: log mode + breakout-volume observation

Next build after E71 (decision items 1 and 3 of the E71 hand-over). **No live behaviour changes**: the Position Stocks gate still defaults to `enforce`, and the new volume check never refuses an entry.

## What changed (services/position-stocks-service)
- `orders/structure_gate.py`: `mode()` is now `off | log | enforce`. In `log` the gate does everything it does in `enforce` (fetch the daily structure, evaluate, count in `/structure/status`, store the snapshot on the position, write the per-day observation row) but `check()` returns no refusal reason - not for a bad location and not for missing data under `STRUCTURE_REQUIRE_DATA`. The snapshot / ring entry say `gate_mode: "log"`, `enforced: false`, `would_reject: true|false`, so you can read what it WOULD have done.
- `config.py`: `STRUCTURE_GATE_MODE` accepts `log` **only when it comes from `PS_STRUCTURE_GATE_MODE`**. The shared name `STRUCTURE_GATE_MODE` is Real Trade's switch (it ships `log`); Position Stocks falls back to it when no `PS_` value is set, so letting it select `log` there would silently turn the scalper's gate off just because Real Trade's is. Through the shared name anything except `off` is still `enforce`, as before.
- Breakout volume (D-vol, same rule as Real Trade): a fresh (<= `STRUCTURE_BREAKOUT_BARS`, 5), not-failed bullish daily BOS whose `ms_bos_vol_ratio` is below `STRUCTURE_BREAKOUT_MIN_VOL_RATIO` (1.2) is a note in `verdict["observations"]`, in the stored snapshot (`observations`, plus `ms_bos_vol_ratio` in its summary) and in the `thin_volume_breakouts` counter on `/structure/status`. There is **no enforce mode** on the scalper: `STRUCTURE_BREAKOUT_VOLUME_MODE` is clamped to `log | off` even if the shared name says `enforce`. A summary without `ms_bos_vol_ratio` is no opinion.
- Calibration page (`control/catalog.py`): `PS_STRUCTURE_GATE_MODE` now offers `enforce | log | off` (ships `enforce`), plus new `PS_STRUCTURE_BREAKOUT_VOLUME_MODE` (`log | off`, ships `log`) and `PS_STRUCTURE_BREAKOUT_MIN_VOL_RATIO` (1.2, 0 = off). The catalog-vs-config drift check passes.
- `.env.example`: the stale structure-gate comment (it said Position Stocks has no `log` mode) is rewritten.
- Tests: `tests/test_e72_log_mode_and_breakout_volume.py` (24): mode values, log never refuses (bad location, no data with REQUIRE_DATA), capture still feeds the observation row, enforce / off unchanged, the config guard (shared `log` stays `enforce`, `PS_` `log` works, `PS_` beats the shared name), enforce clamp for the volume mode, observation cases (thin / enough / stale / failed / bearish / missing / junk / NaN), snapshot + counter + ring, catalog entries.

## Decision 1 is still yours
Nothing here switches the scalper to `log`. To try it: set `PS_STRUCTURE_GATE_MODE=log` (or use the calibration page). Then `/structure/status` and the observation rows (`gate_mode = log`) show what the gate would have refused. Note the observation classifier has no record-only class, so a would-reject row in `log` mode is stored as `rejected_enforced`; filter on `gate_mode` when reading the edge report.
