# E74 - decisions on the E73 open items (2026-10-23)

You asked me to decide the open items myself. Each one below is decided; only the requirements guard is new code.

| Item | Decision | Why |
|---|---|---|
| General R:R floor for Real Trade (decision 2) | **Already in force: `ENTRY_MIN_REWARD_RISK` = 2.0** (entry stop / target, see `RR_FLOOR_1_2_2026-10-22.md`). `STRUCTURE_MIN_RR` stays **0**. | A general floor exists. The structure-based one (reward to next resistance) had a replay edge that flipped sign between seeds (+0.39 / -0.19, group424), so it is not proven. `autocalib` already proposes a walk-forward value; adopt it only when it holds on more than one seed. |
| Regime rules enforce | **Stay log-only.** | No enforce mode exists; adding one means new rule behaviour and thresholds with no outcome evidence. |
| `STRUCTURE_EXIT_MODE` | **Stays `log`.** | `tighten` / `exit` would act on live positions. Revisit after the entry gate has its 15 measured outcomes (B15). |
| C21 pattern signals live | **Stay log-only.** | Needs VM evidence that does not exist yet. |
| Merge the 22 requirements files | **Not merged. Cross-service pin guard added instead.** | Real Trade, Kronos and TimesFM pin an older fastapi / pydantic stack, Kronos needs torch, and one merged file would change running images that cannot be tested here. `scripts/check_requirements_drift.py` now also compares every `services/*/requirements.txt` against the others; today's 12 differing packages are frozen in `scripts/requirements_cross_baseline.json`. A new drifting package or a moved pin fails CI until you run `python3 scripts/check_requirements_drift.py --write-baseline` in the same change. |
| Docker `pip install ./shared` | **Not switched.** Vendored `stockky_ms/` copies stay (generated by `sync_market_structure.py`, checked by `check_shared_copies.py` / `check_ms_package.py` in CI). | Every compose build uses the service folder as its context; the switch needs repo-root contexts in compose and each Dockerfile, which cannot be build-tested here. |
| Gateway router split (109 handlers in `main.py`) | **Not done blind.** | A pure refactor of a 14,260-line file with no pytest / fastapi in the sandbox. It adds no behaviour, so it waits for a session that can run `bash run_tests.sh` after each batch. |

## What changed
- `scripts/check_requirements_drift.py`: `cross_differences()`, `cross_check()`, `--write-baseline`; the normal run now fails on cross-service drift too.
- `scripts/requirements_cross_baseline.json`: the 12 accepted differences (cryptography, fastapi, httpx, numpy, pandas, pydantic, pyotp, sqlalchemy, upstash-redis, uvicorn, websockets, yfinance).
- `scripts/test_check_requirements_drift.py`: 2 new tests (7 total, all pass in a stand-in runner; pytest is not installable here).
- No service code, default or image changed.

## Worth knowing (not changed)
`yfinance` is 0.2.40 in analysis-intelligence but 1.5.2 everywhere else, and Real Trade's `cryptography==41.0.7` is behind the `>=42` the other two services ask for. Both are now visible in the baseline; move them one at a time with their own tests.
