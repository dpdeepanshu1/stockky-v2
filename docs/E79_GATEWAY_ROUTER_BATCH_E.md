# E79 - gateway router split, batch E (2026-10-23)

16 more handlers (18 route registrations) moved out of `services/api-gateway/main.py` into `gateway_support/bound_routes_e.py`, same MainRef method as E55 / E76 / E77 / E78. 60 handlers remain in `main.py` (76 before this batch, by E78's count).

Moved (bodies unchanged except `name` -> `ref.name`): `wake_all_services` (GET + POST `/wake-all`), `momentum_movers_route`, `get_watchlist`, `remove_from_watchlist`, `get_symbol_events`, `get_searched_symbols`, `get_last_scan`, `get_scan_status`, `market_top_gainers`, `market_top_losers`, `market_most_active`, `data_feed_meta` (`/data-feed/meta` + `/api/data-feed/meta`), `stockky_hot_status`, `stockky_hot_result`, `stockky_hot_premarket_status`, `stockky_hot_stop`.

## Why this batch is simple
Unlike E78, no handler here has a main.py name in its signature (the only parameters are `symbol: str` and `task_id: str`), so `bound_routes_e.py` keeps `from __future__ import annotations` like batches B and C. `tests/test_gateway_support_split_e.py` pins that every parameter in this batch is a plain `str` with no default, so a future edit that adds a main.py name to a signature fails the test instead of silently turning a parameter into a query field.

Kept in `main.py` on purpose: `wake_all_services_probe` (a separate handler further down, whose own comment says it used to shadow `wake_all_services`) and `_drop_cache_keys`, `_load_watchlist`, `_save_watchlist` and the other helpers the moved handlers call. Tests patch those as `gw.<name>` and the moved handlers still see the patch through `ref`.

## Checked here
- Route table: all 163 route registrations across main.py and the five factories (E55 / E76 / E77 / E78 / E79) are identical to the E78 zip, in order, with each router expanded at its include site.
- Bodies and signatures: the AST of each moved function (decorators aside) is identical to the E78 original once `ref.` is removed, docstrings and every string constant included. Moved text is byte-preserved: comments are kept, and lines inside multi-line strings are not re-indented.
- Names: every `ref.<name>` exists in main.py (existing guard rule 2, run for this module too); the factory is built once, before the first batch-E include (the build lines sit with the C and D builds).
- Behaviour: original handlers (exec'd from the E78 main.py source) and moved handlers run side by side under fakes: 16 handlers x their argument sets x 192 world variants (wake services all ok / degraded, upstream events 200 / 404 / 500 / raising, momentum scan returning symbols / raising, hot job running / done / empty, KV empty / holding a scan, feed store present / absent), comparing return values, raised exceptions and the ordered log of every collaborator call (Redis reads and writes, feed store calls, HTTP calls, logger calls). 3,648 comparisons, 0 differences. Two deliberately planted bugs (a wrong cache key; `"stopping": True` flipped) are caught by the same script (192 and 64 differences).
- Existing tests that read the moved handlers: `test_main_universe.py`, `test_main_scan_runner.py`, `test_main_market_universe_routes.py` and `test_main_stock_scan_routes.py` call `gw.market_top_gainers()`, `gw.get_last_scan()`, `gw.get_scan_status(...)` etc. and patch them with `monkeypatch.setattr(gw, ...)` / `delattr`; main.py keeps `<handler> = _bound_routes_e.<handler>` for each, so these still resolve. `test_admin_guard.py` scans main.py for admin-protected `@app.post/delete` routes; none of the moved routes carries `dependencies=[Depends(...)]` so its expected set is unchanged.
- Stand-in runner (no pytest here): the new `tests/test_gateway_support_split_e.py` plus the existing split tests: 21 passed, 7 skipped (the live-app tests, which need fastapi); `py_compile` ok.
