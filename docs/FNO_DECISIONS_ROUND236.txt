## Verified from Dhan's docs (was "from memory")

* D1 STOP_LOSS payload: `orderType STOP_LOSS`, `price`, `triggerPrice`, `productType INTRADAY`, `validity DAY`. Matches the code.
* D2 `GET/DELETE /orders/{id}`: `orderStatus` (TRANSIT, PENDING, REJECTED, CANCELLED, PART_TRADED, TRADED, EXPIRED), `filledQty`, `averageTradedPrice`, `remainingQuantity`. DELETE returns 202 with `orderId` and `orderStatus`. Matches the code. The tests use the docs' sample JSON.
* D3 `GET /positions`: `netQty`, `securityId`, `exchangeSegment`, `positionType` (LONG, SHORT, CLOSED). Matches the code.
* D5 Expired options data **exists** (rolling option API, about 5 years, strike as ATM+/-n, Data API plan; the docs say 30 days a call, **measured 9 Nov 2026: one day apart per call (toDate - fromDate at most 1, toDate inclusive), anything wider is HTTP 400 DH-905**). So the strategies CAN get a real-price backtest. Parser, fetch script (`backtest/rolling.py`, `scripts/fno_rolling_fetch.py`), probe (`scripts/fno_rolling_probe.py`) and file checker (`scripts/fno_rolling_check.py`).
* D9 Static IP: only order APIs need it. A non-whitelisted IP is rejected with DH-905. The broker now keeps the DH-9xx code in the error message and explains DH-905.
* Charges: STT on option sell premium 0.15 % from 1 Apr 2026 (confirmed). **NSE option transaction charge is 0.03553 % from 1 Mar 2026, not 0.03503 %: default changed.** BSE option charge 0.0325 % unchanged.

## Code changes that remove a VM dependency

* C6 (real bar interval): every strategy window is now written in minutes and turned into a bar count with the feed's measured interval. 1-, 5- and 15-minute bars give the same rules. With 5-minute bars nothing changed (all old tests pass).
* A1 (SIM has no chain veto): a chain veto is now written to the journal as a `veto` event, so live and SIM can be compared by counting them.
* A3: Signals tab has a Strategy chip on each event; the strategies card marks expiry-day strategies and shows the expiry rules.
