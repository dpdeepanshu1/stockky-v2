# Reward:risk 1:2 (2026-10-22)

**real-trade-service: no change.** It already enforces 2:1 on the entry's stop / target (`ENTRY_MIN_REWARD_RISK`, default 2.0; the entry is rejected below it).
`STRUCTURE_MIN_RR` (reward to the next structural resistance) stays 0 = off: group 424 found its replay edge changed sign between seeds, so it is not proven to help. Say if you want it at 2.0 too.

**position-stocks-service: tightened.** `adaptive.compute()` built a 2:1 target, but the scalp target cap (`SCALP_TARGET_CAP_PCT` 2.5 %) tightened the stop only down to 1.5:1, the bar-level path floored at 1.2:1 and `ADAPTIVE_BAR_TARGET_RR` was 1.8, so live scalps could be placed at 1.2-1.8:1.

| Change | Before | Now |
|---|---|---|
| `ENTRY_MIN_REWARD_RISK` (new, same name as real-trade) | - | 2.0, 0 = off. An automatic entry whose FINAL target% / stop% is below it is SKIPPED with `RR_FLOOR: ...` before depth / circuit / VWAP gates and before any capital is reserved (`orders/rr_floor.py`, wired in `orders/entry.py`) |
| `ADAPTIVE_BAR_TARGET_RR` | 1.8 | 2.0 |
| `SCALP_TARGET_CAP_MIN_RR` | 1.5 | 2.0 |
| bar-level target floor | 1.2 x stop | max(1.2, `ENTRY_MIN_REWARD_RISK`) x stop |

Effect to expect: fewer scalps. A target cut to the 2.5 % cap with a stop that cannot go tighter than its noise floor (0.8 % or 1 ATR) now gives under 2:1 and is skipped instead of placed.
Not covered: manual entries (your explicit pick) are not blocked; exits, stops and trailing are unchanged.
Rollback: `ENTRY_MIN_REWARD_RISK=0` (floor off), and the two defaults above through `.env`. Added to the Real Money Calibration page (Loss-review guards) and protected from auto-calibration.
Tests: `position-stocks-service/tests/test_rr_floor_1_2.py` (7, run, passing: pure parts, shipped defaults, ordering of the check before capital reservation). The catalog-vs-config drift check was run directly and is clean. The DB-backed entry path and the existing position-stocks suites were not run (no pytest / sqlalchemy / httpx in the sandbox).
